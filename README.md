# data-curator

Change management for a corpus of extracted Environmental Product Declarations.
Handles corrections, supersession and expiry with a full audit trail, on Google
Cloud.

Extraction is a separate project. This repository starts from 63 already
extracted EPD records and covers what happens to them afterwards.

## Stack

| Concern | Technology |
| --- | --- |
| API | FastAPI on Cloud Run, private, IAM-authenticated |
| Queue | Pub/Sub, push subscription, dead-letter topic |
| Processing | FastAPI on Cloud Run, push subscriber |
| Storage | BigQuery, partitioned and clustered |
| Scheduling | Cloud Scheduler with OIDC |
| Secrets | Secret Manager, mounted at container start |
| Build | Cloud Build to Artifact Registry, Dockerfile per service |
| Model | OpenAI `gpt-5-mini` behind a provider protocol |
| Schemas | Pydantic v2, enforced structured output |

Python 3.12 in the containers, 3.14 locally.

## Problem

An EPD record changes for three reasons:

1. A reviewer finds an error in an extracted value.
2. The manufacturer publishes a new version of the document, superseding the
   old one.
3. The declaration reaches its validity date and expires.

All three are modelled as a single entity, a **change request**. Sources 1 and 2
arrive over HTTP. Source 3 is generated by a scheduled job. From that point they
share one code path, so a change originating from a clock is screened, logged
and versioned identically to one originating from a person.

## Architecture

```
  reviewer ─────┐
                ├──> API ──> Pub/Sub ──> worker ──> BigQuery
  manufacturer ─┘           (+ DLQ)        │
                                           │  screen()    deterministic rules
  Cloud Scheduler ─────────────────────────┤  triage()    model, conditionally
        │                                  │  finalise()  deterministic rules
        └── raises expiry requests ────────┘
```

The API validates request shape, publishes, and returns 202. It holds no write
permission on the datastore. The worker is the only component that writes to
BigQuery.

## Decision pipeline

`domain/pipeline.py` composes three stages:

**`screen()`** applies deterministic rules: field path resolution, type
stability, and whether applying the change would introduce a validation error
that the record does not already carry. Most requests terminate here at zero
cost and zero latency.

**`triage()`** is reached only by requests the rules cannot settle. The model
receives a compact context block (product identity, cross-referencing physical
properties, declared impacts, the proposal) and returns a classification, a
confidence score and a rationale, constrained by a Pydantic schema the API
enforces.

**`finalise()`** converts the model's opinion into an outcome under rules the
model cannot influence:

- Changes to published figures (`impacts.*`, `date`, `epd_code`,
  `reference_unit`) always route to human review, at any confidence. These
  values propagate into third-party calculations and cannot be silently
  retracted.
- Confidence below 0.85 routes to human review.
- A classification of `implausible` rejects.

The policy lives in `domain/changes.py` as readable, testable code. None of it
is expressed in the prompt.

## Validation

`domain/validation.py` is carried over from the extractor and extended. It
performs deterministic consistency checks on a record: GWP components against
the declared total, material percentages against 100%, packaging exclusion,
end-of-life route totals, variant reference integrity, and density against
thickness and the declared conversion ratio.

The density check was added here. Deciding whether a proposed density was a
decimal error is arithmetic (`density x thickness` equals the declared kg per
unit, a figure the EPD states outright), so it belongs in code. Moving it out of
the prompt removed an unsafe auto-apply, cut model calls by 40%, and produces
zero false positives across the corpus. It is worth porting back to the
extractor, where it would catch the same error class at extraction time.

## Data model

BigQuery dataset `curator`, EU multi-region.

| Object | Type | Contents |
| --- | --- | --- |
| `epd_records` | table | Versioned records, append-only, clustered by `product_id` |
| `epd_current` | view | Highest version per `product_id` |
| `epd_expiry_status` | view | Expiry state derived from `CURRENT_DATE()` |
| `change_requests` | table | Immutable proposals, partitioned by `submitted_at` |
| `change_events` | table | Decisions and reviews, partitioned by `occurred_at` |
| `change_status` | view | Latest event per request |
| `review_queue` | view | Requests awaiting a human, with waiting time |
| `agent_registry` | table | Agents, owners, model, eval scores, review date |
| `agent_registry_attention` | view | Agents unevaluated or overdue review |
| `reconciliation_runs` | table | One row per scheduled run |

Applying a change writes version *n+1* and leaves *n* intact. Historical state
is therefore queryable at any point, which is a requirement for data that gets
cited externally. It also avoids BigQuery's lack of primary keys: enforcing
uniqueness at write time would require a `MERGE` per change or a read-then-write
that races under concurrency.

Per-decision cost, token counts and latency are written to `change_events` and
emitted as structured JSON to Cloud Logging, making spend and drift queryable
from either surface.

## Scheduled reconciliation

`domain/reconcile.py`, invoked nightly by Cloud Scheduler against
`POST /jobs/reconcile` on the worker. It covers two failure classes:

- **Failures**: records past their validity date, requests stuck in review
  beyond an SLA, dead-lettered messages.
- **Drift**: rejection rate above threshold on a sufficient sample, mean model
  confidence below threshold. These produce no errors and no alerts of their
  own, so they require active inspection.

Expired records are not edited in place. The job submits an expiry change
request through the same queue, which produces the same audit trail as any other
change.

## Evaluation

`eval/cases.json` holds 54 labelled change requests derived from the real
corpus, generated by `eval/generate_cases.py`. Cases may corrupt a record before
proposing a change, which is how genuine corrections are represented alongside
bad proposals.

`eval/run_eval.py` exercises the production `decide()` path, so the eval
measures shipped code. It reports two independent figures:

- **Accuracy** against the labelled outcome.
- **Unsafe applies**: changes auto-applied that should have been rejected or
  reviewed. The run fails on any non-zero value regardless of accuracy, because
  the two error directions have asymmetric cost.

Current results:

| Provider | Accuracy | Unsafe | Cost | Model calls |
| --- | --- | --- | --- | --- |
| `stub` | 93% | 0 | $0.000 | 15 / 54 |
| `gpt-5-mini` | 96% | 0 | $0.0136 | 15 / 54 |

The stub is a deterministic offline triager implementing the arithmetic
relationships the prompt describes. It costs nothing, requires no network, and
serves as the baseline a paid model has to beat.

`scripts/register_agent.py` writes the eval summary into `agent_registry`, so
agent quality is queryable alongside ownership and review date.

## Running

Local, no cloud dependencies:

```bash
python -m pytest tests/ -q
python eval/run_eval.py                      # stub provider, free
python eval/run_eval.py --provider openai    # requires .env
```

Cloud, in order:

```bash
bash scripts/setup_gcp.sh          # topics, dataset, service accounts, IAM, secrets
gcloud secrets versions add openai-api-key --data-file=-
python scripts/seed_bigquery.py    # load the corpus
bash scripts/deploy.sh             # build, deploy, wire the subscription
bash scripts/setup_scheduler.sh    # nightly job
bash scripts/smoke_test.sh         # end-to-end verification
```

`. scripts/gcp_env.sh` exports shared configuration and resolves the Cloud SDK's
bundled Python for `bq`, which does not locate an interpreter under Git Bash on
Windows.

`seed_bigquery.py --replace` truncates `epd_records` and reloads at version 1,
discarding version history.

## Design notes

**Queue between ingress and processing.** Decouples availability (a model outage
does not reject submissions), scaling (millisecond validation against
multi-second inference), and enables replay from the dead-letter topic. The API
blocks on publish confirmation before returning 202; acknowledging earlier would
convert a Pub/Sub outage into silent loss.

**Single writer.** The worker holds `dataEditor` on the dataset. The API holds
`dataViewer`. One writer means one place the append-only invariant can be
violated.

**Expiry as an event.** Records load as `active` regardless of date. Stamping
`expired` at load time produced records with no originating request, no
decision, and no timestamp of detection.

**`--ack-deadline=60`.** Measured model latency is 4.7s median, 9.7s p95, with
BigQuery writes following. The 10s default causes redelivery of messages still
being processed successfully.

**Dockerfile over source deploy.** A source deploy uploads a single directory,
preventing two services from sharing `domain/`. A Dockerfile selects the
repository root as build context, so both services copy the same module tree.

**Provider protocol over a framework.** The extractor uses LangGraph because
extract, validate and repair form a cycle that a linear composition cannot
express. Triage is a single call with no loop, and `responses.parse` provides
schema-enforced output natively. `Triager` in `domain/triage.py` is a five-line
protocol; an additional backend is one class. Measured import cost:
`langchain_openai` 8.3s, `openai` 2.8s, which is paid on every cold start of a
scale-to-zero service. The tradeoff accepted is the loss of LangSmith tracing,
replaced by explicit token, cost and latency fields on every log line.

## Operational notes

- Google's front end intercepts `/healthz` on Cloud Run and returns an HTML 404
  before the request reaches the container, even when the route is registered.
  The health endpoint is `/health`.
- `bq add-iam-policy-binding` on a dataset returns `This feature requires
  allowlisting` on standard projects. Dataset grants go through the dataset
  access list; see `scripts/grant_dataset_access.py`.
- Cloud Scheduler POSTing an empty body receives 411 from the front end.
  `--message-body={}` supplies a Content-Length.
- The worker requires `pubsub.publisher` on the changes topic. It is
  predominantly a consumer, and the requirement only surfaces when the
  reconciliation job first raises an expiry request.

## Known limitations

The eval under-tests the model. Cases the model handled well were subsequently
absorbed into deterministic rules, so headline accuracy now largely reflects the
rule layer. Expanding coverage of genuinely undecidable cases is outstanding
work.
